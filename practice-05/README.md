## Эксперимент с очередями выполнения

| Этап | Порядок меток | Объяснение |
|---|---|---|
| Прогноз до запуска | A, F, C, E, B, D | Синхронный код (A, F), затем микрозадачи Promise (C, E), затем макрозадачи таймера (B, D) |
| Фактический результат | A, F, C, E, B, D | Полностью совпало с прогнозом модели Event Loop |

- Синхронный код выполняется немедленно в текущем стеке вызовов (A, затем F).
- Микрозадачи `Promise.then` помещаются в очередь microtask queue и выполняются сразу после завершения текущего синхронного стека до макрозадач (C, затем E).
- Макрозадачи `setTimeout` (даже с задержкой 0) помещаются в macrotask queue и планируются на следующий тик цикла событий (B, затем D).

## Организация кода

| Файл | Ответственность |
|---|---|
| `api/server.mjs` | Локальный HTTP-сервер на чистом Node.js (без внешних зависимостей), реализующий REST API для задач и категорий. |
| `src/api-client.js` | Транспортный клиент HTTP: формирование URL (`buildUrl`), отправка запроса через `fetch`, таймауты (`AbortSignal`), типизация ошибок в `ApiError`. |
| `src/task-api.js` | Прикладной модуль API: валидация фильтров перед отправкой, методы `getTasks`, `getTaskById`, `getCategories`, `loadInitialData` (`Promise.all`). |
| `src/variant.js` | Индивидуальный вариант 1 студента и его параметры фильтрации (`completed: false`). |
| `src/main.js` | Клиентский сценарий запуска в Node.js, вывод таблицы задач и демонстрация перехвата ошибки 404. |

| Сценарий | Ожидаемый `kind` | Фактические поля `ApiError` | Итог |
|---|---|---|---|
| Задача `999` | `http` | `status: 404`, `code: "TASK_NOT_FOUND"` | Успех |
| `completed=yes` | `http` | `status: 400`, `code: "INVALID_QUERY"` | Успех |
| `/debug/error` | `http` | `status: 503`, `code: "SERVICE_UNAVAILABLE"` | Успех |
| `/debug/invalid-json` | `invalid-response` | `cause: SyntaxError` | Успех |
| `/debug/delay?ms=5000` | `timeout` | `kind: "timeout"` | Успех |
| Внешняя отмена | `aborted` | `kind: "aborted"` | Успех |
