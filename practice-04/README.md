## Эксперименты с формой и хранилищем

| № | До запуска: прогноз | После запуска: результат | Объяснение |
|---:|---|---|---|
| 1. Пустое обязательное поле | Браузер не отправит форму из-за `required` | Отправка заблокирована нативно | Атрибут `required` активирует валидацию браузера до события `submit` |
| 2. Название из пробелов | `required` может пропустить пробелы, но скрипт отклонит | Прикладная валидация выдала ошибку | `required` считает строку с пробелами непустой, поэтому необходим вызов `.trim()` |
| 3. Типы значений `FormData` | Все поля будут строковыми (`string`) | Все поля получены как строки | `FormData` возвращает значения текстовых полей и `select` как `string` |
| 4. Строка в `localStorage` и JSON | `localStorage` хранит только строки | Прочитан JSON, распарсен в объект | `localStorage` сохраняет строку через `JSON.stringify` |
| 5. Повреждённый JSON | `JSON.parse` выбросит исключение | Перехвачено `SyntaxError` в `try/catch` | Необходима конструкция `try/catch` для безопасного fallback |

## Организация кода

- `task-service.js`: чистая бизнес-логика манипуляций с массивом задач без побочных эффектов.
- `form-validation.js`: валидация и нормализация полей черновика формы (`id`, `title`, `priority`) без взаимодействия с DOM.
- `task-storage.js`: безопасная сериализация, валидация структуры сохранённых данных и работа с `storage`. Принимает `storage` аргументом для изоляции и тестируемости.
- `task-view.js`: построение DOM-элементов карточек, сводки и пустых состояний.
- `main.js`: координация состояния, обработка событий пользователя, вызовы сервиса и сохранение.
